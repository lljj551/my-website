# zhangruidong-site

张睿栋的单页实验站点：**手势绽放的粒子花 + 五星评分 + Canvas 反应力挑战**。
纯静态、零构建、无后端，只用 localStorage 存数据。

> 当前状态：**Phase 2 · 第 2 屏射击已完成**。
> 第 1 屏手势粒子、五星评分、第 2 屏 5 组射击与成功 / 失败结算均已接入；
> 本机最佳成绩 / 历史场次仍留待 C 阶段。

---

## 1. 运行

| 方式 | 命令 | 能用到什么 |
| --- | --- | --- |
| 直接双击 | 打开 `index.html` | 布局、评分、结算预览；**摄像头/手势不可用**（`file://` 限制） |
| 本地 HTTP（推荐） | 双击 `serve.cmd`，或 `python -m http.server 5173` | 全功能，含 MediaPipe Hands 手势 |
| Node 环境 | `npx serve . -l 5173` | 同上 |

打开 `http://localhost:5173/`。首次会请求摄像头权限；拒绝后自动降级为「点按手动绽放」。

调试参数：

- `?debug` — 控制台输出状态迁移与粒子参数
- `?bloom` — 跳过摄像头，300ms 后自动播放完整的 2.8s 绽开
- `?final` — 跳过动画，直接看绽放终态 + 五星评分（验收版式用）
- `?reveal` — 只显示评分态，粒子保持花苞
- `?preview=result` — 用假数据打开结算层，检查第 3 屏排版
- `?flat` — 关闭平滑滚动并直接落到第 2 屏（截图 / 验收用）

```

├── index.html                  语义结构：第1屏 / 第2屏（内含结算层）/ 全局导航
├── serve.cmd                   可选：一键启动本地静态服务（摄像头需要）
├── README.md
├── css/
│   ├── base.css                设计令牌、重置、按钮、右侧章节导航、系统提示条
│   ├── hero.css                第1屏：粒子画布层次、CSS 兜底花苞、提示、评分星标、相机监视窗
│   ├── challenge.css           第2屏：标题、规则、HUD、Canvas 战场、倒计时
│   └── result.css              第3屏：内联结算层（覆盖在战场内，不新增滚动屏）
└── js/                         全部经典脚本（非 ESM），保证 file:// 直接双击也能加载
    ├── config.js               命名空间 ZRD、常量、工具函数、事件总线
    ├── storage.js              localStorage 封装（带内存降级）
    ├── particles.js            A · Three.js 粒子（花苞 → 绽放）
    ├── hand-tracker.js         A · MediaPipe Hands + 开掌判定状态机
    ├── game.js                 B · Canvas 射击：倒计时、靶标、命中、HUD
    ├── results.js              C · 评级、结算渲染、最佳成绩/历史写入
    ├── hero.js                 A/C · 第1屏流程编排、相机接线、五星评分交互
    └── main.js                 启动、环境体检、滚动监听、模块接线、调试参数
```

**依赖（全部 CDN，无本地包）**

- Three.js `0.160.0`（UMD 全局 `THREE`）
- MediaPipe Hands `0.4.1675469240`（全局 `Hands`，wasm/模型也走同一 CDN）
- Canvas 2D 为原生 API，无库
- 字体：Google Fonts（Chakra Petch / JetBrains Mono / Noto Sans SC），失败时回退系统字体

> 为什么不用 ES Module：`<script type="module">` 在 `file://` 下会被 CORS 拦死，
> 与「双击 index.html 可直接运行」冲突。因此所有脚本用经典脚本 + `window.ZRD` 命名空间。

## 3. 三个模块的边界

### A · 手势粒子与绽放（`particles.js` + `hand-tracker.js` + `hero.js`）

- 粒子：`THREE.Points` + `ShaderMaterial`（`AdditiveBlending`），桌面 4200 / 移动 3000 颗
- 形态：紧致花苞（冷色、低亮、呼吸）→ 随机球面外推目标 + 弹簧阻尼逼近 → 冷色向暖色过渡
- 时序：2.8s `easeOutCubic`；绽开结束后才淡入姓名与评分
- 手势：仅取一只手；以「手腕 → 中指 MCP」归一化，食指 / 中指 / 无名指 / 小指的
  `指尖到腕 / PIP 到腕 > 1.5`，四指同时满足并连续 500ms 才触发一次
- 视频：不进入主视觉，仅在右下角保留 148px 监视窗；绽放结束后关闭摄像头、停止手势
- 兜底：摄像头权限拒绝 / 无摄像头 / 模型加载失败 → 自动跳过手势并直接显示评分，粒子保持花苞漂浮
- `file://` / 移动端 → 保留「点按手动绽放」，流程仍可走完
- 10 秒未检测到手：追加「没有检测到手？请确保光线充足，手掌距离摄像头 40~80cm」

### B · 反应力挑战（`game.js`）

- 共 5 组，每组随机 2~4 个目标，悍匪与人质混合（至少各 1 个）
- 目标存活时间严格为 2500 / 2000 / 1600 / 1300 / 1000 ms；同组目标同时出现
- 圆形命中判定：点击坐标到圆心距离 `< r`；命中悍匪 +1 并闪白，命中人质立即失败
- 超时悍匪计入漏网，不直接判负；5 组结束且未误伤人质即成功
- 成功页展示命中率（命中悍匪 / 总射击；0 次射击显示 `—`）与「漏网悍匪：X 名」
- 准星、50ms 枪口闪光、命中粒子全部由 Canvas 绘制；无音频、无游戏引擎

### C · 结算与评分（`results.js` + `hero.js` + `storage.js`）

- 结算层内联覆盖在第 2 屏战场，`role="dialog"`、`Esc` 回到顶点、锁背景滚动
- 成功 / 失败两种状态：`挑战成功` / `任务失败——你击中了人质`，均带「重新挑战」
- 五星：hover/focus 预览、方向键 / Home / End；点击 append 一条评分到 `zrd_ratings`
- 平均分实时重算并显示 1 位小数；已评分时回填上次星数，提示「你上次打了 X 星，可以重新评分」
- localStorage 读写全部包在 try/catch 中，隐私模式下降级为会话内存，不阻断页面
- 本机最佳成绩 / 历史场次尚未写入（C 阶段剩余）

## 5. 数据与事件契约

**localStorage（唯一持久化；评分键为 `zrd_ratings`）**

```jsonc
{
  // 原始值是 JSON 字符串；scores 每次评分 append，lastUpdated 为 ISO 时间
  "zrd_ratings": "{\"scores\":[5,3,5],\"lastUpdated\":\"2026-10-26T10:28:24.228Z\"}",

  "zrd:best:v1":    "1280",              // 历史最高分（B/C 阶段使用）
  "zrd:history:v1": "[{\"ts\":1730000000000,\"score\":1280,\"acc\":0.76,\"avgReaction\":404,\"rank\":\"A\"}]"
}
```

评分读取时会校验结构：坏 JSON、越界分数、缺失字段都按空数组处理；
写入失败（隐私模式 / 配额满）时保留在内存，页面继续可用。

**模块间事件（`ZRD.bus`，避免互相 import）**

| 事件 | 载荷 | 发出方 |
| --- | --- | --- |
| `hand:status` | `{ phase, message }` | hand-tracker |
| `hand:track` | `{ present, score, ratios, holdMs, holdTarget }` | hand-tracker |
| `hand:open` | `{ score, ratios, heldMs }` | hand-tracker |
| `hand:error` | `{ code, message }` | hand-tracker |
| `particle:bloom-end` | `{}` | particles |
| `hero:reveal` | `{ source }` | hero |
| `rating:change` | `{ value, summary }` | hero |
| `game:start` | `{ rounds }` | game |
| `game:hit` | `{ type, hits, shots }` | game |
| `game:miss` | `{ x, y, shots }` | game |
| `game:end` | `{ outcome, stats }` | game |
| `result:open` / `result:close` | `{ outcome }` / `{}` | results |
| `sys:note` | `{ text, ttl }` | 任意模块 → main 顶部提示条 |

**公开调试句柄**：`window.__ZRD__`（`hero` / `game` / `results` / `particles` / `hands` / `store`）

### 第 1 屏验收步骤

1. 双击 `serve.cmd`，打开 `http://localhost:5173/`，允许摄像头
2. 页面中央出现「请将手掌正对摄像头，然后张开手指」，右下角出现取景窗
3. 手掌正对镜头，四指张开并保持 0.5 秒 → 粒子由冷青花苞绽开为暖金粒子，约 2.8s
4. 姓名与五星浮现；点星后平均分 / 次数立刻更新，摄像头自动关闭
5. 刷新页面 → 回填上次星数，显示「你上次打了 X 星，可以重新评分」
6. 遮住摄像头 10 秒，提示下方应出现光线 / 40~80cm 的小字
7. 拒绝权限 / 无摄像头 / 模型加载失败：应直接出现姓名 + 五星，顶部提示已跳过手势；粒子保持花苞漂浮

### 第 2 屏验收步骤

1. 向下滚动到「反应力挑战」，规则面板应出现：
   「射中所有悍匪，射中任意一名人质即失败。共 5 组，速度越来越快。」
2. 点击「开始挑战」→ 3-2-1 倒计时；鼠标移动时 Canvas 内出现十字圆环准星
3. 命中悍匪：白色闪光 → 目标闪白消失，SCORE +1，SHOTS +1
4. 命中人质：立即停止，显示「任务失败——你击中了人质」+「重新挑战」
5. 不误伤人质完成 5 组：显示「挑战成功」、命中率、漏网悍匪小字
6. 完全不射击：5 组超时后仍应成功，命中率显示 `—`，漏网数等于超时悍匪总数
7. 成功 / 失败页点击「重新挑战」→ 回到倒计时；「回到顶点」→ 回到第 1 屏

## 9. 已知边界

- **移动端手势不可用**：第 1 屏不请求摄像头，显示「当前设备建议使用桌面端」；评分与射击仍可触屏完成。
- **摄像头需要 localhost 或 HTTPS**：`file://` 双击打开时浏览器会拦截摄像头与 MediaPipe wasm，手势不可用；第 2 屏不受影响。
- **localStorage 仅存在当前浏览器**：评分历史不跨浏览器 / 设备同步；隐私模式或禁用存储时降级为会话内存，刷新即丢。
- **第三方资源依赖 CDN**：Three.js / MediaPipe Hands / Google Fonts 断网或被拦截时，对应视觉或手势会降级，页面其余部分仍可用。
- **手势判定按固定阈值**：四指伸展比 `> 1.5` 且连续 500ms；极端拍摄角度、逆光或手掌倾斜可能无法触发，可调 `config.js` 的 `openPalmThreshold` / `openPalmHoldMs`。
